# Facial Expression Recognition on FERPlus

This repository compares four ways of classifying facial expressions on the FERPlus dataset. Models tested include a HOG and SVM baseline. Also tested are a CNN trained from scratch using 48×48 images and two ImageNet-pretrained models (ResNet-18 and EfficientNet-B0) which are fine-tuned using 224×224 images. All models are trained on the same six classes, are split and weighted in the same way, and are evaluated with the same metrics. Models are compared using confusion matrices and Grad-CAM visualizations. Robustness to noise, occlusion and low-light is also assessed.

## Repository layout

```
data/              preprocessed FERPlus arrays (.npy, not in git)
models/            trained weights written by the notebooks
notebooks/         the seven notebooks, run in order (01-07)
results/           metrics, figures, CSV files and LaTeX tables written by the notebooks
streamlit_app.py   optional demo app that runs the trained models on a photo
requirements.txt   Python dependencies
```

There is no common code package. Every notebook contains all the code it needs. Similarly, the demo app has its own version of the model and preprocessing code.

## Setup

Python 3.12 was used. First, create a virtual environment and install packages from `requirements.txt`:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Data

The notebooks read nine NumPy arrays of preprocessed FERPlus data. Due to their large size (about 1.6 GB), these are not stored in git and are instead provided separately. Place them directly in `data/`:

| File | Shape | Used by |
|---|---|---|
| `FER2013{Train,Valid,Test}_48_images.npy` | `N x 48 x 48`, `uint8` | HOG + SVM, CNN from scratch |
| `FER2013{Train,Valid,Test}_224_images.npy` | `N x 224 x 224`, `uint8` | ResNet-18, EfficientNet-B0 |
| `FER2013{Train,Valid,Test}_labels.npy` | `N`, string labels | all models |

Although the data arrays contain all eight original FERPlus classes, Disgust and Contempt are excluded during loading. This produces six classes: Neutral, Happiness, Surprise, Sadness, Anger and Fear.

## Reproducing the results

Execute notebooks in sequence. Results are output to the `results/` directory. Trained model weights are also saved in `models/`. Notebooks 06 and 07 analyze outputs generated by previous notebooks. Notebooks 01, 02, 06 and 07 operate on a CPU. However, notebooks 03-05 train models and were executed on Google Colab with an NVIDIA T4 GPU. In all cases, a fixed random seed (42) was used.

| Notebook | Runs on | Writes |
|---|---|---|
| `01_data_exploration.ipynb` | CPU | `results/class_weights.json`, exploration figures |
| `02_hog_svm.ipynb` | CPU | `models/hog_svm.joblib`, `results/metrics/hog_svm.json` |
| `03_cnn_scratch.ipynb` | Colab GPU | `models/cnn_scratch.pt`, `results/metrics/cnn_scratch.json` |
| `04_resnet.ipynb` | Colab GPU | `models/resnet18.pt`, `results/metrics/resnet18.json` |
| `05_efficientnet.ipynb` | Colab GPU | `models/efficientnet_b0.pt`, `results/metrics/efficientnet_b0.json` |
| `06_comparison_gradcam.ipynb` | CPU or GPU | `results/comparison.csv`, `results/tables/comparison.tex`, `results/tables/per_class_f1.tex` |
| `07_noise_robustness.ipynb` | CPU | `results/robustness.csv`, `results/tables/robustness.tex` |

Every notebook also saves its figures to `results/figures/`.

### 01 - Data exploration

This notebook verifies that image and label data match. It analyzes the class balance to demonstrate why Disgust and Contempt are excluded. Sample images are displayed and average faces and pixel values analyzed. Duplicate test and training images are identified. Finally, inverse frequency class weights are calculated; these are applied by all models.

### 02 - HOG + SVM baseline

Here, the baseline model (HOG, standardization, PCA and SVM) is trained. Hyperparameters for HOG and SVM are optimized on a stratified sample of 8,000 training images, and each setting is scored by macro F1 on the validation data. The optimal model is subsequently trained on all training data and then evaluated once on the test data. On a CPU, this process takes around 10 minutes.

### 03 - CNN trained from scratch

A VGG-like CNN is trained from scratch on 48×48 images. A small grid search over the hyperparameters (learning rate, head dropout and network width) identifies the combination giving the highest macro F1 on the validation data. The optimal model is then trained for up to 60 epochs with early stopping. On a T4 GPU, the final training session lasted around 42 minutes. Including hyperparameter searches, training took around 100 minutes.

### 04 - ResNet-18 and 05 - EfficientNet-B0

Both notebooks fine-tune ImageNet-pretrained models on 224×224 images in two stages. Initially, just the new six-class head is trained (the backbone is held fixed) for 3 epochs. Next, the backbone (or only its final stages) is unfrozen and trained, at a learning rate 10 times lower than that of the head. Limited hyperparameter searches are undertaken to establish how many layers of the backbone should be retrained, and the appropriate backbone learning rate. Including the tuning runs, ResNet-18 required around 66 minutes and EfficientNet-B0 around 42 minutes of T4 GPU time.

### 06 - Model comparison and Grad-CAM

This notebook collates metric data for the four models. Metrics include test and clean test scores, class-wise F1, confusion matrices and training curves. Grad-CAM visualizations are also generated for the three networks, which requires their weights in `models/`.

### 07 - Robustness to noise

Finally, this notebook analyzes (but does not re-train) the four models' performance on corrupted test data. Five severities of Gaussian noise, random occlusion and low-light are analyzed. In addition, two further sets of data are analyzed, where either the eyes or mouth are occluded. Approximately 45 minutes are required to execute this notebook on a CPU. Results are therefore saved in `results/robustness.csv`. Set `RECOMPUTE = True` to analyze the models again, for instance after they have been retrained.

### Running notebooks 03-05 on Colab

The first code cell connects to Google Drive and transfers the data to the Colab computer. Model weights and metrics are then stored on Drive. There is no need to clone the repository, as each notebook contains all of its code.

1. Upload the nine `.npy` files to `MyDrive/ferplus/data` on Google Drive.
2. Open the notebook in Colab, choose a GPU runtime (T4) and run all cells.
3. Copy the outputs from Drive into the repository:
   - `MyDrive/ferplus/results/metrics/*.json` to `results/metrics/`
   - `MyDrive/ferplus/results/figures/*.png` to `results/figures/`
   - `MyDrive/ferplus/models/*.pt` to `models/`

On Colab, training duration depends on GPU availability as these are shared. Outputs may also vary marginally depending on hardware.

## Results

Test data comprises 3,103 images across the six classes. Clean macro F1 is based solely on the 2,874 test images which do not also appear in the training data.

| Model | Test accuracy | Test macro F1 | Clean macro F1 | Parameters |
|---|---|---|---|---|
| HOG + SVM | 0.708 | 0.631 | 0.596 | 20,032 support vectors |
| CNN (scratch) | 0.836 | 0.790 | 0.781 | 4.8 M |
| **ResNet-18** | **0.875** | **0.831** | **0.825** | 11.2 M |
| EfficientNet-B0 | 0.859 | 0.808 | 0.797 | 4.0 M |

Robustness data from notebook 07: the average macro F1 on test data across the five different severities of each type of corruption, and also where the eyes or mouth are occluded. The proportion of the clean macro F1 retained by each model is shown in parentheses. Note that models were not re-trained for this analysis.

| Model | Gaussian noise | Occlusion | Low light | Eyes hidden | Mouth hidden |
|---|---|---|---|---|---|
| HOG + SVM | 0.428 (68%) | 0.432 (68%) | **0.625 (99%)** | 0.295 (47%) | 0.226 (36%) |
| CNN (scratch) | 0.508 (64%) | 0.665 (84%) | 0.569 (72%) | 0.564 (71%) | 0.582 (74%) |
| ResNet-18 | 0.520 (63%) | **0.712 (86%)** | 0.698 (84%) | 0.594 (71%) | **0.650 (78%)** |
| EfficientNet-B0 | **0.540 (67%)** | 0.668 (83%) | 0.670 (83%) | **0.625 (77%)** | 0.557 (69%) |

## Demo app

While not essential for reproducing results, the demonstration application loads models from `models/`. It then detects a face in a user-uploaded or webcam image and displays Grad-CAM visualizations alongside the predicted class scores. As in notebook 07, a sidebar allows users to corrupt a detected face in the same manner.

```bash
streamlit run streamlit_app.py
```
